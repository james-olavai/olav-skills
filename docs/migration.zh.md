# 从生成包或旧平台迁移

独立产品使用单一发行包 `olav-skills`、Python 命名空间 `olav_skills` 和管理命令 `olav-skills`。Olav Skills 0.2 包含七个标准技能及其确定性 runtime。旧生成包独立安装的 `runtime/`，以及 `olav` / `olav_netops` 命名空间，都不是新包依赖或导入别名。

## 逐消费者迁移

1. 记录旧解释器、包版本、技能发现根与授权数据根，保留环境及备份/锁文件。
2. 在**新独立 venv** 安装 0.2.0，执行 `version`、`doctor` 和[合成示例](offline-data.md)，不要原地替换运行中的旧服务环境。
3. 将新资源导出到独立审阅目录，比较 API 与导入。自定义 Python 消费者改用 `olav_skills`；没有把旧导入静默转向新包的别名。
4. 显式解决同名技能和项目/用户重复注册，再从新解释器安装到选定宿主范围。手工旧目录不会自动归属新安装器，详见[归属与升级](installation.md)。
5. 选择新的 `OLAV_HOME`，测试授权数据副本。迁移该消费者前核对精确设备集合、解析缺口、时间戳、有界结果及产物。
6. 单独验证真实宿主发现与模型行为。消费者通过自身验收前保留旧 venv 和资源。

`.olav` 布局与环境变量名继续沿用，但这**不保证所有历史数据库兼容**。上述命令不会自动转换用户数据。恢复旧 venv 也不能撤销数据写入；回退需要授权备份或可丢弃副本。

## 源码与集成边界

本仓是原生产品的维护源码，`provenance/` 记录首次官方提取及命名空间/资源转换。后续原生修改直接在此维护，不要用旧公开生成器覆盖，也不要保留第二份 runtime 实现。

Open WebUI 集成、旧 API-client 及 DuckLake 服务端消费者各有独立合同。原生包测试不验收其部署，也不授权服务切换。本包的 [portable 知识导出器](portable.md)可用，但保留的工作流仅为元数据，没有模拟器或工作流引擎。旧平台宿主、记忆、服务调度及模型自动循环不属于独立产品。

## 旧发行状态

旧 `olav` 与 `olav-netops` 项目已发布 `0.27.0.post1` 退役通知版。历史发行文件和 yank 状态保留；PyPI 独立的 Archived 状态仍需 owner 操作。通知版不代表旧文件删除或源码仓归档。现有消费者仍须各自验证迁移。

Skills 命令以当前手册为准，[历史归档](legacy-index.md)仅供旧上下文。发行、源码同步、旧包归档与部署是不同操作；更新本地文档不会改变现役服务，也不会重新发布不可变的 0.1.1 产物。现有[许可证](license.md)和声明继续适用。
