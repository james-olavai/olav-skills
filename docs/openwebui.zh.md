# 在 Open WebUI 中查询网络数据

本指南适用于已配置 Olav 集成的 Open WebUI。查询以你有权访问的租户所保存的网络记录为依据。管理员决定你的账号能选择哪些租户入口、使用哪些只读能力及下载哪些文件。

## 体验公开 Demo

[Olav Demo](https://olavai.com/zh/demo/)使用两个独立租户的合成网络数据。使用分配给你的账号和租户入口。查询和下载链接限定在账号获授权的租户内。按 Demo 页面说明申请访问即可。

## 开始对话

1. 打开管理员提供的 Open WebUI 地址，用分配给你的账号登录。
2. 在模型选择器中，选择管理员为目标租户配置的入口。
3. 用平常的说法提问。如果回复提供了文件链接，请用发起请求的账号登录并点击下载。

以下对话和数字均为虚构示例。

## 查设备总数和角色覆盖

> **你**：“现在有多少设备？”
>
> **回复**：“当前租户的台账记录了 12 台设备。这是已登记的数量，设备的实时状态未知。”

> **你**：“核心交换机有多少台？”
>
> **回复**：“总数未知。我能核对的 5 台设备里，0 台确认是核心交换机，2 台可明确排除，3 台缺少判定所需的信息。”

库存数量按台账记录统计。按角色计数还需要设备类别和角色证据。第二段回复只覆盖一页记录，这一页的统计无法确定整个租户的核心交换机总数。

## 下载完整的当前设备台账

> **你**：“把设备清单做成一份能下载的报告。”
>
> **回复**：“这份 Markdown 报告包含当前租户台账中的全部 12 台设备，点击报告链接即可下载。”

回复确认完整交付后，下载 **Markdown 报告**可查看该租户的完整当前台账。报告包含设备名、管理地址、平台、厂商、型号和角色六列，未记录的值保留为缺失。

如果回复也提供了 `returned-results.csv`，它用于核对本轮查询实际返回的记录，覆盖范围以这些返回记录为限。

## 查看拓扑图的覆盖范围

> **你**：“给我画个拓扑图。”
>
> **回复**：“本次来源共有 8 条二层邻接记录，图里画出了查询返回的 2 条。图和随附报告依据的是同一批返回记录。”

回复同时提供图和报告时，可以打开两份文件，先从报告确认来源和覆盖范围。图上的边只描述本次结果里的邻接记录，全网覆盖和实时连通性仍未得到证实。

## 范围不清或证据缺失时

| 你问 | 回复示例 |
| --- | --- |
| “重要的那几台，能给我整理个名单吗？” | “你指的是哪些设备？可以告诉我设备名称，或说明按什么条件筛选。” |
| “上个月有多少台设备？” | “现有资料缺少上个月的台账证据，历史数量未知。” |
| “只要有管理地址的设备。” | “现有记录无法确定哪些设备符合这个条件，无法核实完整的筛选清单。” |
| “只发分公司的清单。” | “现有记录无法确定哪些设备属于分公司，无法核实这份清单。” |

如果回复在确认范围，可以补上设备名称、筛选条件或地点。历史数量和筛选清单仍需要对应时点、字段或地点的证据。清单范围无法确定时，回复会请你澄清或说明缺少哪些证据，并省略设备名单和下载链接。

## 在本地使用独立包

公开的 `olav-skills` Python 包提供命令行、技能资源及已有 AI 宿主的绑定方式。Open WebUI 的登录、租户选择和网页下载由已配置的私有集成提供。本地使用请参阅[独立包安装指南](installation.zh.md)。
