# 原生内省缓存

0.2 在原生导入收尾时刷新两个 DuckDB 表，用于发现字段和候选值。

| 表 | 内容 |
| --- | --- |
| `netops.value_profile` | 每个入选视图、文本列和非空值一行，包含频数、指纹和聚类编号。 |
| `netops.introspection_cache` | 一行，包含设备清单投影、视图字段及类型、状态类值分布和 `refreshed_at`。 |

## 覆盖范围

目录覆盖本次原生收尾中成功重建的快照投影、二层投影以及按命令生成的视图。没有可支持解析结果的命令不进入本次刷新。若命令或适用数据消失，旧视图仍可能可查询。下一次成功收尾会将它从目录和值分布中移除。源表确实存在但为空时，仍可为其中的空投影生成一行目录。JSON 聚合值为 NULL，表示上次成功刷新时该部分没有符合条件的记录。

值分布统计不同非空值有 1 至 30 个的文本列，跳过设备、接口、快照 ID 和地址等身份及维度字段。重复观测也计入行频数。目录只收录列名以 `status`、`state`、`proto` 或 `oper` 等状态类词结尾的值分布。聚类编号按单个视图、单个字段内的指纹排序，可帮助发现拼写差异。合并值前还需核实其领域含义。

## 刷新与失败

原生收尾先让旧目录失效，再重建视图和值分布。使用可写的原生连接并启用自动提交时，必要的读取或构建失败后，目录不可用。缺少目录时，可以查询已授权的数据源。已有事务中的刷新由调用方决定提交或回滚。SQL 失败可能使 DuckDB 事务中止。回滚会还原该事务范围内的源数据和缓存。

在收尾过程之外改动输入，不会自动刷新缓存。`refreshed_at` 记录数据库刷新所在事务的时钟。采集时间应以采集来源为准，历史事实应通过绑定明确快照的查询确认。自动视图可能跨设备和命令组合不同快照标识。请通过受限查询核实快照成员、数量、来源覆盖和观测到的健康状态。此合同适用于原生 DuckDB，宿主能力保持由宿主授权。
