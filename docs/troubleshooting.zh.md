# 故障排查

记录精确解释器、包版本、所选数据根、脚本名、stdin 参数、退出码、JSON stdout 及独立 stderr。缺陷报告不要包含秘密或完整客户配置。进程退出成功还不够，应检查结果的 `status`/`ok`，以及真实返回数据和产物。

## 安装与发现

| 现象 | 检查和下一步 |
| --- | --- |
| `doctor` 不通过 | 用绝对 venv 解释器执行，检查缺失模块/资源，在该环境重装审阅过的发行包 |
| 看不到技能 | 核对项目/用户范围、发现路径及实际配置，检查重复注册并刷新宿主 |
| 拒绝非归属目标、已编辑文件或符号链接 | 保存并审阅精确冲突目录；审阅后只将该技能移出发现目录，再安装 |
| 解释器路径已不存在 | 从替代 venv 对同一范围重新安装绑定；只安装 wheel 不会刷新已复制技能 |
| Pi 自定义用户目录找不到 | 安装器用户范围固定 `.pi/agent/skills`，不读取 `PI_CODING_AGENT_DIR`；使用项目范围或显式配置宿主 |

CLI 没有强制覆盖或卸载命令。归属与手工移除边界见[安装](installation.md)。

## 输入与导入

`validate_bundle` 返回 `ok: false` 时停止并检查错误。内容 SHA-256 不一致时应取得正确来源包，不能绕过校验或修改哈希来迁就损坏内容。校验器要求规范目录；其它支持格式先走 [importer](skills/importer.md) survey 流程，后续使用返回的新准备路径。

导入可能保存原始文本，却未产生结构化行。请读 `parse_report`、`report_path`、未解析原因和无结构化数据设备；区分刻意 raw-only、未注册解析器及解析器错误。首个导入仍在运行时不要启动第二次；大采集包应在宿主设合适超时。查询前核对真实 `db_path` 和快照 ID。

## 查询与证据

- **表/视图不存在：**核对相关 context/schema 和解析覆盖。未采集协议是缺口，不是健康的空数据集。
- **数据不对或意外陈旧：**在 Python 启动前核对 `OLAV_HOME`、CWD 与继承路径覆盖项。使用导入返回的真实快照 ID。
- **`ambiguous_snapshot_time`：**检查采集来源并明确选择授权快照。按名称排序或用导入时间代替未知时间，会改变问题。
- **预期两行却只看到一行：**检查 `has_more`、`next_offset`、单元格/字节裁剪和有效限制。稳定查询保持相同条件分页，或缩小字段投影。总量未知时保留未知。
- **`needs_sql_generation`：**只有 `query` 会返回 schema，应提供审阅后的 `sql`。本包不会通过模型端点生成 SQL。
- **日期证据为空：**检查 `date_scope`、排除项及未知时间候选；翻到末尾之外也不等于没有匹配。
- **外部 SQL 访问或修改被拒绝：**使用受支持读取入口。`requires_approval` 不授权也不执行管理操作。

## 产物与解析器候选

图表要检查 `status`、节点/边数及实际文件。`too_wide` 要求缩小范围；转换器的省略注释不是成功图表。读权限正常也不代表可写输出，请选择授权可写的输出/CWD。

`finish_learn` 返回 `invalid` 时不会冻结文件。根据诊断修正，补充不同样本后复测。单样本 TextFSM 成功即启用，可能过拟合；低样本 Python 候选可能隔离。详见[解析器流程](workflows/parsers.md)。

报告产品缺陷前，用新合成根复现，附最小授权输入及语义预期；不要为了排查文档示例直接修生产数据库或旧 venv。
